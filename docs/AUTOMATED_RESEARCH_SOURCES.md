# Automated research source coverage

## Current adapters

| Adapter | What it collects | Credentials | Bounds and failure handling | What it does not prove |
|---|---|---|---|---|
| DEX Screener discovery/enrichment | Candidate token profiles, chain/contract metadata, pool and market observations | No key configured by this repository | HTTP errors are surfaced by the existing source module; provider limits may change and must be checked against current DEX Screener documentation | Official identity, buying intent, safety, or qualification |
| Candidate project homepage collector | Bounded HTML metadata, page text excerpt, outbound link candidates, keyword-trigger candidates | No key | Public HTTP(S) URLs only; 8-second timeout; 1 MB body limit; at most 40 links and 20,000 characters of text; successful results cached for 24 hours by stable prospect fingerprint; fetch failures are explicit and leave statuses unknown | That the candidate homepage is official, that keyword matches are verified events, or that a criterion is satisfied |
| Linked and global RSS/Atom trigger feeds | Dated event candidates from RSS/Atom feeds linked by candidate project pages plus global CoinDesk and Cointelegraph news feeds; matches project name, symbol, or contract against trigger-related titles/summaries | No key for these public RSS feeds | Up to 2 project feeds per prospect plus 2 global feeds per run; 8-second timeout; 1 MB response limit; at most 100 entries/feed; 6 concurrent workers; successful feeds cached for 24 hours; fetch failures stay explicit | Verified buying intent, authoritative event attribution, or complete news coverage |
| Public chain-explorer identity cross-check | Explorer page, chain identifier, token name/symbol metadata, candidate-site contract mention, explorer-listed domain, project-linked public accounts, and contact-route candidates | No API key; HTML explorer pages are best-effort | Configured Ethereum, BNB Chain, Base, Polygon, Arbitrum, Optimism, and Solana explorer pages; 8-second timeout, 1 MB response cap, up to 3 transient-failure attempts, 4 concurrent fetches; unsupported chains and failed pages remain unknown; heuristic confidence is explicitly not a probability | Official identity, absence of impersonation, or canonical verified/mismatch status |
| GoPlus Token Security API + Honeypot.is | Contract-level security flags plus independent EVM buy/sell simulation observations for configured chain IDs | No API key is configured; public endpoint is used | GoPlus and Honeypot.is queried independently; 8-second timeout; response capped at 1 MB; up to 3 attempts for transient network and HTTP 408/425/429/5xx failures; successful combined results cached for 24 hours; secondary-provider failure is retained separately and never implies safety | Global risk clearance, project reputation, source completeness, or identity verification |
| RugCheck Solana Token Report + optional GoPlus Solana Token Security API | Solana mint risk reports plus independent mint/freeze/close authority and mutable-token observations | RugCheck public endpoint needs no key; GoPlus Solana requires the optional `GOPLUS_ACCESS_TOKEN` GitHub Actions secret | 8-second timeout; response capped at 1 MB; up to 3 attempts for transient network and HTTP 408/425/429/5xx failures; successful results cached for 24 hours; GoPlus Solana is skipped explicitly when its secret is absent and failures remain unknown | Global risk clearance, project reputation, source completeness, or identity verification |

Global news feeds currently configured are [CoinDesk RSS](https://www.coindesk.com/arc/outboundfeeds/rss/?outputType=xml) and [Cointelegraph RSS](https://cointelegraph.com/rss). Project-linked feeds and these global feeds are fetched as dated-event candidates only; they do not create verified buying-trigger reviews.

## GoPlus coverage

The adapter currently maps Ethereum, BNB Smart Chain, Polygon, Arbitrum, Optimism, Base, Avalanche C-Chain, Fantom, Cronos, Gnosis, Linea, Scroll, and Mantle names to provider chain IDs. Configured EVM records query GoPlus and Honeypot.is independently; Solana mints use RugCheck and optionally GoPlus Solana when `GOPLUS_ACCESS_TOKEN` is configured. Honeypot.is supports Ethereum, BNB Smart Chain, and Base according to its published chain documentation; other configured chains are not assumed supported. Chain aliases are explicit in `src/beliquid/security_research.py`; unrecognized chains are not guessed. Confirm current API support and terms before relying on a newly added chain.

Configured high-severity GoPlus flags include reported honeypot behavior, inability for some holders to sell, hidden owner capability, self-destruct capability, external-call capability, and owner-controlled balance changes. RugCheck reports are classified by explicit security/reputation concerns such as rug history, honeypot/scam indicators, LP unlocked risk, and active mint/freeze authority; generic low liquidity and low LP-provider counts remain review-level market-quality signals rather than automatic security holds. Other capabilities such as minting, proxy behavior, blacklist, transfer pause, cooldown, holder concentration, and inability to buy are recorded as review-level observations unless the provider evidence explicitly indicates a high-severity concern.

A high-severity provider finding creates an automated hold in the research queue. The canonical identity/risk review file and qualification score are not silently rewritten. A report with no configured high-severity flags is labeled `no_high_risk_flag_detected_by_provider`, not `clear`; no report is `unknown`, never safe. A provider flag is a source-backed concern that warrants conservative routing, not conclusive proof of malicious intent.


## Deterministic criterion assessment

The workflow emits `identity-crosscheck.json`, then `automated-criterion-assessment.json` and `automated-criterion-reviews.json` before rebuilding the final prospect exports. The identity cross-check fetches configured chain-explorer pages and compares token name/symbol metadata, the candidate website's exact contract mention, whether the explorer lists that website domain, and project-linked public account/contact paths. At this stage, only positive assessments for a narrow set of dated public-event criteria can be emitted: two distinct allowlisted publishers (CoinDesk and Cointelegraph), publication timestamps within 72 hours, similar titles (Jaccard token similarity at least 0.4), and strong entity matching (exact contract address, or both project name and token symbol). Publisher domains are checked against the event URLs. This was added specifically to avoid generic-name false positives such as unrelated news being matched to a project called “Launching”.

The deterministic rules can confirm project credibility/team access only when the identity cross-check finds all configured corroboration signals (candidate-site contract mention, explorer symbol match, explorer-listed candidate domain, and public account/contact paths). They can confirm buying-trigger timing, growth/strategic potential, or explicit service-need language only when the relevant event terms and two-source news corroboration rule are satisfied. They never emit `not_present`; single-source, undated, mismatched, unsupported, or absent evidence remains `unknown`. A confirmed criterion still contributes only its configured weight, and the existing 60% evidence threshold controls whether a numeric score is issued. The identity cross-check's strongest state is `corroborated_candidate`, not `verified`; it never changes canonical identity/risk status. Criterion assessment does not clear canonical risk, change the six weights, or enable outreach. In practice, this deliberately narrow rule set may issue no scores until stronger corroborated evidence exists.

## Pipeline and task behavior

- `automated-research.json`, `trigger-research.json`, and `security-research.json` are collected from the initial discovery export. The deterministic criterion assessor then produces a validated review input and rebuilds the final prospect CSV/JSON exports before queue generation.
- The research queue consumes the security output and routes a reported high-severity finding to an automated hold before commercial research.
- The queue does not convert source results or the identity candidate-match score into canonical identity verification or a clean risk review.
- Qualification still uses the existing six criteria and configured 60% evidence-coverage threshold. Candidate keywords and security flags do not automatically confirm criteria or generate a score.
- Task completion is not qualification or clearance. Outreach remains disabled. Durable state contains public evidence URLs and prospect identifiers only; never put credentials or secrets in the state issue.
- The audit manifest records SHA-256 hashes of the research outputs, deterministic criterion assessment and generated review input. Hashes establish artifact integrity, not the truth of a source statement.

## Remaining limitations

This is an initial independent contract-risk integration, not a complete security or reputation engine. Configured EVM chains now query GoPlus and Honeypot.is independently; Solana can query RugCheck and optional GoPlus Solana, but the latter requires the `GOPLUS_ACCESS_TOKEN` secret and otherwise remains unknown. Honeypot.is can return no report for a supported chain/token and that is not safety evidence. There is not yet multi-provider Solana coverage, comprehensive reputational/news-source coverage, a canonical identity cross-match against official contract announcements, comprehensive buying-trigger coverage beyond feeds linked by candidate project pages, or automated criterion-level evidence assessment across all six criteria. Public-page keyword matches remain candidates only. Criterion-level evidence assessment across all six criteria remains incomplete. No failed call should be represented as a completed task.

Provider rate limits and terms can change. The adapter uses bounded retries for transient failures but does not assume a fixed request quota. If GoPlus returns rate limiting or provider errors, the output preserves the failure state and does not mark the prospect clear. RugCheck and Honeypot.is currently use public endpoints without a configured key. GoPlus Solana requires `GOPLUS_ACCESS_TOKEN`; add it under repository Settings → Secrets and variables → Actions if that source is enabled. The workflow passes it only as an environment variable; the collector never writes it to artifacts or logs.
